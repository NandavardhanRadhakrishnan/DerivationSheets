# Handoff: T-19 Reject conditions on input rows (merged)

## Objective

T-19 (decision D-8): allow `[[row.reject]]` on input rows and make validate, the graph, eval, cases, the rendered page and the editor handle them.

## Done

- **Merged:** PR #4, merge commit `615de84` on `main` (commit `c8d359d`); CI green; `go test ./...`, `go vet ./...` and gofmt clean locally. Branch `reject-on-input` deleted locally.
- `internal/validate/validate.go`: `reject-on-input` removed. On an input row, `reject.N.when` names rows directly (no `uses`), the same rule as an input's `when`; undefined names give `ref-undefined` with the label (`reject.0.when refers to ...`).
- `internal/graph/graph.go`: `IsRejectWhen(key)`; names in an input's `when` and reject conditions become its deps, so the page grid shows them and eval reads the input after them.
- `internal/eval/eval.go`: rejects run only when the step is not unknown, all deps are known, and the status is not `not-required` (no-op for derived rows, whose unknown deps already make them unknown).
- `internal/cases/cases.go` `valuePool`: literals in the input's own reject conditions join its pool, last (numbers with c-1 and c+1; quoted strings for string inputs). Without this, `weight_kg > 30` and `subtotal > 1000 && !is_member` stayed uncovered.
- `docs/format.md` (field table, Expressions) and `schema/sheet.schema.json` (row `reject` description).
- Tests: `TestInputRejects` (validate), `TestInputReject*` (eval), `TestInputRejectsCovered` (cases), `TestSaveSheetInputReject` (editor). The validator and eval tests were confirmed to fail on the old code.
- Checked by hand on a scratch copy: validate 0 errors, cases 19 of 19 targets, `serve` page shows both rejects and the Member dot on Subtotal.
