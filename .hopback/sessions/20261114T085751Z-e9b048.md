## Gotchas
- `requirements --apply` must use the explicit form `main..HEAD` until T-29 is fixed; the default form fails with `product: reading .dsheets/sources/...`. Cause: locate() in internal/requirements/run.go counts a fetched copy under <repo>/.dsheets/sources as a file of the flow's repo, so Repo=product and the path is the cache path.
- A derived row with a ternary formula never gets a type, so --apply refuses with 'type unknown'; its message advises giving the row a type, which the format rejects on derived rows (derived-input-key). Covered by T-28.
- In the editors, change the flow first (unpin), then the sheet; the other order leaves a flow the editor cannot open (T-31).
- The editors bump `version` on every save and write a new cases.toml next to a sheet that had none; expect both in diffs.
- The sandbox needs git and go; setup.sh and the scenario scripts need Git Bash and python. Stop every running dsheets editor before setup.sh, since it rebuilds .bin/dsheets.exe. After setup.sh, delete any PM clone: its remotes are gone.
- Restore `specs/` before tests or merge in this repo (`git checkout -- specs/`); stash `.hopback/` with `--include-untracked` when switching branches.
